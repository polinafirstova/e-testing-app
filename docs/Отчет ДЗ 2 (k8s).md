# Домашнее задание №2. Основы Kubernetes

## 1. Использованные абстракции Kubernetes

Для развертывания системы электронного тестирования в кластере Kubernetes использовались следующие стандартные объекты:

- **Deployment:** контроллер, который управляет запуском контейнеров. Всего создано три деплоймента: `postgres-db` (база данных), `backend-api` (серверная часть) и `frontend-app` (клиентская часть). Деплоймент следит, чтобы приложение всегда работало, и позволяет мгновенно увеличивать число копий программы командой `kubectl scale`.
- **Pod:** изолированная среда, внутри которой физически запускается и работает Docker-контейнер. Поды создаются автоматически деплойментами.
- **Service:** сетевой объект, который создает постоянный и неизменяемый адрес для группы подов. Поды могут перезапускаться и менять свои внутренние IP-адреса, но сервисы `postgres-db` и `backend-api` гарантируют, что компоненты всегда найдут друг друга по стабильному сетевому имени внутри кластера.
- **PersistentVolumeClaim:** запрос на выделение постоянного места на жестком диске, в данном случае для базы данных (`postgres-pvc`). Благодаря этому все вопросы и результаты тестов не сотрутся, если под базы данных перезапустится или обновится.

## 2. Взаимодействие сервисов между собой

Внутри кластера Kubernetes компоненты общаются по следующей схеме:

1. **База данных (`postgres-db`):** запускается в одном экземпляре, подключает диск PVC для хранения данных и открывает внутренний порт `5432` для кластера.
2. **Бэкенд (`backend-api`) → база данных (`postgres-db`):** сервер считывает настройки сети из переменных окружения. Вместо конкретного IP-адреса в поле `DB_HOST` указано имя K8s-сервиса — `postgres-db`. Внутренний DNS-сервер Kubernetes сам переводит это имя в текущий IP-адрес базы данных. Бэкенд успешно подключается по стандартному порту `5432`.
3. **Фронтенд (`frontend-app`) → бэкенд (`backend-api`) через nginx-прокси:** на фронтенде указан относительный базовый адрес запросов: `API_BASE_URL = '/api'`. Внутри пода фронтенда работает веб-сервер nginx. Когда пользователь проходит тест, его браузер отправляет запросы на порт фронтенда, nginx перехватывает эти запросы и с помощью правила `proxy_pass` сам пересылает их внутрь кластера на стабильный адрес бэкенда `http://backend-api:5000`.
